# Meta-Lexicon Storage Layer

## Overview

The meta-lexicon is a versioned storage layer for parameters, domains, structural patterns, operators, invariants, metrics, and safety constraints used by the Meta-Crystal generator.

**Purpose:** Separate technical facts from runtime code, provide a structured format for semantic descriptions, and enable future retrieval and validation.

**Key Principle:** Machine facts are extracted from runtime code; semantic descriptions are added later by LLM or manual review. The lexicon does not modify runtime behavior.

## Layer Separation

### Machine Layer (`machine/`)
- **Purpose:** Technical facts extracted from runtime code
- **Source:** `metacrystal_engine_v7.py`, `profile-presets.ts`, `sidecar.py`
- **Contents:** Parameter names, types, defaults, provenance
- **Editing:** Only via `extract_runtime_lexicon.py` script
- **Status:** Read-only source of truth for technical facts

### Semantic Layer (`semantic/`)
- **Purpose:** Human-readable descriptions for future retrieval
- **Source:** Manual editing or LLM (DeepSeek, etc.)
- **Contents:** Display names, descriptions, synonyms, query phrases
- **Editing:** Manual or LLM-assisted
- **Status:** Pending - currently empty templates

### Validated Layer (`data/meta_lexicon/validated/`)
- **Purpose:** Runtime-ready lexicon (merged machine + semantic)
- **Source:** Built from machine and semantic layers
- **Contents:** Complete entries with both technical and semantic data
- **Editing:** Generated by `build_lexicon.py`
- **Status:** Build artifact

### Relations Layer (`relations/`)
- **Purpose:** Compatibility, conflicts, taxonomy
- **Source:** Manual verification only
- **Contents:** Confirmed relationships between entries
- **Editing:** Manual with human review
- **Status:** Defer - not auto-generated

## Usage

### 1. Extract Runtime Facts

Extract technical facts from the current runtime generator:

```bash
cd python_engine
python lexicon/scripts/extract_runtime_lexicon.py
```

**What it does:**
- Reads `metacrystal_engine_v7.py`, `profile-presets.ts`, `sidecar.py`
- Extracts EngineConfig fields, domain flags, structural patterns, metrics
- Creates entries in `machine/` directory
- Generates provenance report in `reports/runtime-provenance.json`
- Generates missing descriptions report in `reports/missing-descriptions.json`

**When to run:**
- After adding new parameters to EngineConfig
- After modifying domain flags
- After adding new structural patterns
- After updating UI profile presets

### 2. Validate Lexicon

Check schemas, IDs, references, and types:

```bash
cd python_engine
python lexicon/scripts/validate_lexicon.py
```

**What it validates:**
- All IDs are unique
- Required fields are present
- Entity types and statuses are valid
- Namespace matches entity type
- Relation references resolve
- Type consistency (default_value matches type)
- Range consistency (min_value <= max_value)
- Provenance information for runtime-used entries

**Output:**
- Console summary
- Detailed report in `reports/validation-report.json`

**Exit code:** 0 if valid, 1 if validation fails

### 3. Build Validated Lexicon

Merge machine and semantic layers into runtime-ready lexicon:

```bash
cd python_engine
python lexicon/scripts/build_lexicon.py
```

**What it does:**
- Merges machine facts with semantic descriptions
- Applies relations if available
- Creates snapshot of previous validated lexicon
- Writes merged entries to `data/meta_lexicon/validated/`
- Generates build report in `reports/build-report.json`

**When to run:**
- After updating machine layer
- After adding semantic descriptions
- Before deploying to production

### 4. Add Semantic Descriptions

**Manual editing:**
1. Copy template from `templates/`
2. Fill in semantic fields
3. Save to `semantic/` directory
4. Run `build_lexicon.py`

**Future LLM-assisted:**
- DeepSeek will fill semantic fields
- BGE-M3 will index entries
- Retrieval will find parameters by natural language

## Runtime Chain

The lexicon follows the confirmed runtime chain:

```
UI: src/components/pages/Generation.tsx
  ↓
API: src/app/api/generate/start/route.ts
  ↓
Runner: src/lib/engine/runner.ts
  ↓
Sidecar: python_engine/sidecar.py
  ↓
Engine: python_engine/metacrystal_engine_v7.py
  ↓
Storage: data/meta_crystals/crystals/
```

**Provenance tracking:**
- Each entry records source files, symbols, and lines
- UI component, frontend field, API field, sidecar field, Python field
- Extraction method (config, ast, enum, manual)

## Editing Guidelines

### Machine Layer (`machine/`)
- **DO NOT** edit manually
- **DO NOT** modify technical facts
- **DO NOT** change defaults, types, or ranges
- **USE** `extract_runtime_lexicon.py` to update

### Semantic Layer (`semantic/`)
- **CAN** edit manually
- **DO NOT** modify technical fields
- **ONLY** fill semantic fields (display_name, description, synonyms, etc.)
- **MUST** keep `needs_human_review` accurate

### Relations Layer (`relations/`)
- **CAN** edit manually
- **ONLY** add confirmed relationships
- **DO NOT** infer from names alone
- **REQUIRES** human verification

## Adding New Entity Types

1. Create schema in `schema/`:
   ```json
   {
     "$schema": "http://json-schema.org/draft-07/schema#",
     "allOf": [
       { "$ref": "lexicon-entry.schema.json" },
       { "properties": { "entity_type": { "const": "new_type" } } }
     ]
   }
   ```

2. Create template in `templates/`

3. Update extractor to handle new type

4. Update validator to check new type

5. Update build script to include new type

## Safety Rules

### What the Lexicon Does NOT Do
- Does NOT modify runtime generator
- Does NOT change parameter defaults
- Does NOT affect current ranking
- Does NOT run generation automatically
- Does NOT create embeddings (yet)
- Does NOT connect to DeepSeek (yet)

### What the Lexicon DOES Do
- Stores technical facts separately
- Provides structure for semantic descriptions
- Enables validation of parameters
- Tracks provenance from UI to Python
- Prepares for future retrieval

## Troubleshooting

### Extraction fails
- Check that source files exist
- Verify Python can read TypeScript files
- Check regex patterns match current code structure

### Validation fails
- Check `reports/validation-report.json` for details
- Look for duplicate IDs
- Check for unresolved relation references
- Verify type consistency

### Build fails
- Ensure machine layer is valid
- Check that semantic layer (if present) is valid
- Verify output directory permissions

## Important Notes

1. **Source of Truth:** Runtime code (`metacrystal_engine_v7.py`) is the source of truth for technical facts. The lexicon is a mirror.

2. **No Runtime Impact:** The lexicon does not affect current generator behavior. It's a separate storage layer.

3. **Read-Only Extraction:** The extractor is read-only. It does not modify source code.

4. **Manual Review Required:** Semantic descriptions require human review before being marked as validated.

5. **Relations Deferred:** Compatibility and conflict relations require separate verification. Do not auto-generate.

6. **No Embeddings Yet:** Embedding vectors and vector indexes are not implemented in this phase.
