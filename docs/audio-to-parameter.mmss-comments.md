# Комментарии к ремонту MMSS Audio-to-Parameter

## Результаты сверки

Проверены три целевых документа относительно текущего кода, прежде всего `src/components/pages/AudioToParameterPage.tsx`, `src/lib/audio-segment-timeline.ts`, `src/lib/morpho/jobs.ts` и `src/app/api/audio-to-parameter/segment/route.ts`. Исходный код не изменялся.

### Найденные несоответствия документов и внесённые исправления

- В JSON `task.artifact_type` был `module`, а `artifact.composition_level` — `substack`. Содержание описывает связанные UI/API/timeline/process компоненты, поэтому тип исправлен на `substack`.
- Обычное представление описывалось слишком кратко. Теперь сказано отдельно: исходные массивы `clap` и `siglip` хранятся раздельно; `mergeFrames` строит обычное объединение с приоритетом CLAP при совпадении `technical_name`; только при включённом Blend оно заменяется результатом `blendParameterFrames`. В коде это подтверждено. Это различие описания, не дефект кода.
- Мета-формула не отражала точное поведение `currentFrame` на границах. Она дополнена случаями пустой линии, времени до первого узла, первого/последнего узла, отсутствия следующего узла, равных времён и выключенной интерполяции.
- Уточнено, что при отсутствии параметра в одном кадре `interpolateParameterFrames` возвращает копию целого параметра из `a`, если `ratio < 0.5`, иначе из `b`. Это подтверждённое поведение кода; прежняя формулировка «из ближайшего соседа» была недостаточно точной, особенно на равенстве.
- Список `dependencies` смешивал обязательные кодовые/внешние capability связи и действия по запросу. Причины уточнены по веткам; callbacks WaveSurfer выделены в отдельный список, suppliers помечены как источники входов, seek-ответ обозначен как поток данных/callback, а отмена — как поток команды. Эти двусторонние обмены не представлены как цикл prerequisite dependencies.
- Критерии качества документа отделены от поведенческих критериев модулей. Непроверенное выполнение в браузере/процессе не стало критерием уже выполненного анализа документа.
- Утверждение об окончании/тайм-ауте Morpho уточнено: `runMorphoAudioSearch` завершает Promise в `close`/`error` callback; отдельный таймер тайм-аута для этого процесса в просмотренном коде не обнаружен. Тайм-аут 10 минут передаётся CLAP через `callSidecar`, он не является тайм-аутом Morpho. `maxDuration` route не доказывает фактическое завершение дочернего процесса по истечении времени.
- Авторские пояснения JSON переведены на русский. Стабильные ключи/идентификаторы, имена функций, enum и точные значения контрактов оставлены без перевода.

### Замечания, которые сверка подтвердила

- Выбранная композиция `substack` соответствует фактическому сочетанию UI, API, TypeScript преобразований и Python путей.
- Раздельные массивы движков, обычное объединённое представление с CLAP-приоритетом и отдельный опциональный Blend подтверждаются `mergeFrames`, `macroParameters` и UI conditional rendering.
- При наличии только одного параметра функция интерполяции копирует выбранную сторону целиком; это корректное описание после уточнения правила порога.
- Suppliers, callbacks и data flow являются разными отношениями; их следует отличать от обязательной prerequisite зависимости. В коде WaveSurfer сообщает React-состоянию длительность/время, а seek request идёт в обратном направлении.

## Различение результатов

- **Несоответствие описания:** перечисленные выше неточности исправлены в документах.
- **Подтверждённый дефект кода:** в этой сверке не устанавливался; исправления ограничились описанием.
- **Непроверенный вопрос:** фактическое поведение browser UI, загрузка моделей, завершение/отмена под нагрузкой, тайм-аут внешнего запуска и качество retrieval не проверялись исполнением.

## Ограничения выполненной проверки

Запущена повторная проверка JSON доступным PowerShell парсером и статическая проверка внутренних ссылок/основных контрактов. Тесты, UI, API, Python, CLAP/SigLIP2, GPU и индексы не запускались. Поэтому синтаксическая и статическая проверка документов не является проверкой поведения приложения.
