## Изменения

- `src/lib/rag-v3/query-concepts.ts`: детерминированная декомпозиция запроса по пунктуации и связкам EN/RU, IDF-фильтрация и веса концептов.
- `src/lib/rag-v3/composite-index.ts`: max-cosine ranking по нескольким query-векторам с сохранением score каждого концепта.
- `src/lib/rag-v3/search.ts`: независимые Qwen-векторы концептов, отдельный atom-vector, relation bias и обязательное покрытие концептов/сторон активной relation в Top-K.
- `src/lib/rag-v3/relation-index.ts`: загрузка 12 relation-векторов, trigger gate, cosine threshold и adaptive alpha.
- `src/lib/rag-v3/alignment.ts`: согласование Top-K по концептам и relation-группам; диагностическая реализация Sinkhorn оставлена выключенной по согласованной политике.
- `python_engine/anchoring_v3/build_relation_anchors.py`: 12 relation anchors, Qwen embeddings, binary Float32 и инкрементальный SHA-256 no-op rebuild.
- `python_engine/anchoring_v3/anchoring.py`: для каждого параметра выбирается ближайший query-концепт; relation direction уточняет value anchor; Text/String/Array работают в детерминированном retrieval-only режиме без LLM.
- `src/lib/rag-v3/search.ts`, `python_engine/anchoring_v3/anchoring.py`: Select option matching ограничен явными командами `mode/option/режим/вариант` или явным technical name, поэтому опции вроде `bass` и `dark` не захватывают обычный звуковой запрос.

## Relation anchors

Построены: `cutoff_resonance`, `warmth_brightness`, `saturation_cleanliness`, `attack_decay`, `attack_release`, `sustain_decay`, `dry_wet`, `stereo_width_mono_center`, `reverb_size_decay`, `pitch_slide_portamento`, `lfo_rate_depth`, `modulation_stability`.

Контрольные запросы:

- `dark cutoff plus screaming resonance`: в Top-K одновременно присутствуют `simple_lowpass_filter_cutoff_hz` и resonance-параметры; каждому value matcher передан свой концепт.
- `acid bass`: активируется `cutoff_resonance`; Top-K гарантированно содержит по параметру cutoff и resonance, в detail зафиксированы relation и confidence `0.831`.
- `warm analog`: активируется `warmth_brightness` с confidence `0.718`; направление brightness отрицательное, relation `bright` не активируется как отдельная противоположная команда.
- повтор одного и того же запроса: полный JSON массива results совпал (`repeat_equal=true`).

## Text / String / Array

Зафиксированная политика выполнена буквально: `retrieval > default`, LLM выключена. Если dataset содержит `value_candidates`, `published_values` или options, выбирается существующее значение; иначе сохраняется default с явным source `not_generated`. Проверка старой semantic matrix для Text/String включает metadata/provenance targets, которые закономерно исключены scope по умолчанию; поэтому её `target retrieved` не является критерием sound retrieval. Array target извлечён 10/10. Генеративных значений и недетерминированных LLM-вызовов нет.

## Известные ограничения

- Один неоднозначный synthetic Range target для `soften the texture` не попадает в Top-K 12; итог остаётся 9/10.
- Relation membership строится детерминированным lexical match по текущему dataset; это не learned pairwise head.
- Sinkhorn оставлен выключенным: relation bias и обязательное concept coverage уже дают Complex 10/10, поэтому дополнительная транспортная перестановка не применяется.
- Для Text/String без опубликованных альтернатив значение намеренно остаётся default и маркируется `not_generated`, как требует согласованная retrieval-only политика.
